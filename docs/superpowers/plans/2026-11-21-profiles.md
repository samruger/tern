# Profiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Named paper profiles that run every variant under their own settings, side by side with today's desk (profile 1), with every settings change logged and results split by settings period.

**Architecture:** One engine. Profile 1 is `runtime/` as it is. Each extra profile is `runtime/profiles/<id>/` with its own `config.json`, its own `Shadow` records and a settings log. On every step the engine runs each enabled profile's `Shadow.step` on the snapshot it already fetched, each inside its own try/except. The screen shows a profile by overlaying that profile's data onto the status dict, so the existing panels draw it unchanged.

**Tech Stack:** Python 3.11+, standard library only, curses; tests are `unittest` in `tests/test_tern.py`.

**Spec:** `docs/superpowers/specs/2026-11-21-profiles-design.md`

## Global Constraints

- Standard library only; no new dependencies.
- Profile 1's existing files in `runtime/` are never moved or rewritten by profile code. The only new profile-1 file is `runtime/settings-log.jsonl`.
- Profiles 2+ are paper only: no order is ever sent for them and they have no live or gate settings.
- No new Kalshi requests per step, except coins a profile turns on that nothing else fetches.
- At most 8 profiles besides profile 1 (`MAX_PROFILES = 8`).
- A deleted profile's folder moves to `runtime/profiles-deleted/<id>-<YYYYMMDD-HHMM>/`; nothing is erased.
- Profile 1 can't be disabled or deleted.
- Every new shadow row carries `"sv"`. Rows without it are period 0 ("before profiles").
- Changing a variant or enabled flag is logged but does not bump `sv`; a change to a record field does.
- Bounds: band low 0.50–0.98, band high 0.51–0.99, steps 0.01, low < high; max spread 0.01–0.10, step 0.01; slots chosen from 30/25/20/15/10/5, at least one on; at least one coin on; contracts, most an hour and paper start use `config.SETTINGS` bounds.
- Fees: every profile uses profile 1's `taker_fee`.
- The web screen sends no profile commands; it only views.
- Run tests with `python3 -m unittest tests.test_tern` (pytest is not installed).

## Review Focus

1. A profile name that is empty, a duplicate, all symbols or has `../` or `/` → a safe, unique id (`profile-2`, `profile-2-2`, ...); never a path outside `runtime/profiles/`.
2. Engine restarted mid-hour → a profile takes no second entry in a slot it already took (its `shadow.json` keeps slots, as profile 1's does).
3. A profile's `config.json` hand-edited into something unreadable → that profile keeps its last good settings (or is skipped with a logged error); profile 1 keeps trading.
4. Raising band low past band high one step at a time → refused with a message; never saved.
5. Deleting the profile the screen or a web tab is viewing → that view falls back to profile 1 with a note, no crash.

### Task 2: `tern/profiles.py`: profiles on disk, their settings and the settings log

**Files:**
- Create: `tern/profiles.py`
- Test: `tests/test_tern.py` (new class `Profiles`)

**Interfaces:**
- Consumes: `config.Config`, `config.Strategy`, `config.load(dir, fallback)`, `config.save(cfg, dir)`, `config.SETTINGS`, `config.SERIES`, `shadow.Shadow`, `shadow.VARIANTS`.
- Produces:
  - `MAX_PROFILES = 8`; `SLOT_CHOICES = (30, 25, 20, 15, 10, 5)`
  - `RECORD_KEYS = ("strategy.band_lo", "strategy.band_hi", "strategy.minutes", "strategy.max_spread", "strategy.series", "strategy.contracts", "strategy.max_hour_cost")`: fields that change how records are made (bump `sv`).
  - `PROFILE_SETTINGS: list[config.Setting]`: rows for the settings box of profiles 2+, groups PROFILE (`strategy.variant` kind `"variant"`, `enabled` kind `"bool"`), RULE (`strategy.band_lo`/`band_hi` kind `"p"`, `strategy.minutes` kind `"slots"`, `strategy.max_spread` kind `"p"`, `strategy.series` kind `"coins"`), PAPER (`strategy.contracts`, `strategy.max_hour_cost`, `paper_capital` copied from `config.SETTINGS`). Bounds as in Global Constraints.
  - `class SettingsLog(path: str)`: `.sv -> int` (last line's `sv`, else 1); `.append(key, was, now, bump: bool) -> int` writes `{"ts","sv","key","from","to"}` with the new `sv` and returns it; `.lines() -> list[dict]`.
  - `diff_record(old: Strategy, new: Strategy) -> list[tuple[str, object, object]]`: `(key, was, now)` for each `RECORD_KEYS` field that differs.
  - `slug(name: str, taken: set[str]) -> str`: lowercase `[a-z0-9-]`, others to `-`, trimmed, empty → `"profile"`, made unique with `-2`, `-3`...
  - `class Profile`: attrs `id, name, enabled: bool, created: float, dir: str, cfg: Config, log: SettingsLog, shadow: Shadow`; `Profile.load(dir, fee) -> Profile`; `.save_meta()` (writes `profile.json` `{"name","enabled","created","sv"}`); `.reload_cfg() -> list[tuple]` (re-reads `config.json` with the current cfg as fallback; logs and bumps `sv` once per changed record field via `diff_record`; returns the changes); `.set(key, value) -> tuple[object, object]` (checks bounds, raises `ValueError` with a message the screen can show, saves, logs, bumps `sv` iff `key in RECORD_KEYS`); `.step(event, close, markets, now, vol)` (no-op when disabled; else `shadow.step(..., S=self.cfg.strategy, sv=self.log.sv)`).
  - `load_all(runtime: str, fee: float) -> list[Profile]` (sorted by `created`; a folder that fails to load is skipped and its error returned via `load_errors`, see below); `load_errors: dict[str, str]` module-level, last error per folder.
  - `create(runtime: str, name: str, base: Config, fee: float) -> Profile`: raises `ValueError` past `MAX_PROFILES`; copies `base.strategy` and `base.paper_capital`; first log line `key "created"`, `sv` 1.
  - `delete(runtime: str, pid: str) -> str`: moves the folder, returns the new path; refuses anything not directly under `runtime/profiles/`.
